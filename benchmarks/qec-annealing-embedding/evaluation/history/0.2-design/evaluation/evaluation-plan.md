# Design acceptance plan — not an executed evaluation

## Current scope

Question authoring and create-benchmark requirements audit only. The user explicitly deferred reference experiments, model screening and difficulty calibration. This plan records the meaning of the task's acceptance criteria; it neither launches work nor provides a reference answer. No numerical claim has been measured.

## Intended assessment of future research outputs

| Dimension | Evidence required by the question |
|---|---|
| Mathematical fidelity | A valid CSS interface; exact minimum-cost syndrome objective; sound ground-state projection attaining the optimum; stated ties, penalties, offsets and scales; complete stabilizer/logical success conventions. |
| Independent validation | Code commutation, exact small-case reduction/projection checks, valid disjoint connected branch sets, realization of every interaction, and physical coefficient consistency. Larger uncertified claims remain heuristic. |
| Scientific comparison | At least two defensible designs and automatic reference, matched targets/budgets, controls separating formulation and embedding changes, resource and coefficient-scale tradeoffs rather than one isolated score. |
| Transfer and reproducibility | Toric family with complete wraparound checks, explicit Steane case, independent syndrome sets, hashes/versions/seeds, reusable code and portable outputs. |
| Claim discipline | Hardware claims conditional on actual limits; no offline quantum-speedup inference. Decoding or recovery claims need the corresponding controlled evidence and uncertainty. Negative conclusions require evidence beyond timeouts. |

Alternative encodings, auxiliary representations, embeddings and justified tie rules are valid if they satisfy the same invariants. No author-preferred recipe or exact selected embedding is a hidden answer. Float tolerances must be justified from the chosen arithmetic and energy scales; exact binary algebra is checked exactly.

## Budgets and later calibration

This open research question requires the researcher to declare and charge offline budgets before comparisons. It does not yet define a fixed-budget scored test. A later scored version must specify numerical resources and any performance target in the solver-visible prompt before trials. Reference readiness and difficulty remain untested; later evidence can motivate a new version. There is no claim that structural checks establish difficulty.

## Design-only checks now

Check standalone completeness, public references, consistency of statement/PDF, optional fixture integrity, workspace structure and provenance. These are document and input checks, not decoding or embedding experiments. No A/B trial, one-hint screening, reference pilot or full research execution belongs to this revision.
